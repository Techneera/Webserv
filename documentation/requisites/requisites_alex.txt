WEBSERVER

    SHALL...

    ...remain operational at all times.

    ...receive communication attempt from the browser/request
        (parsing HTTP)

    ...respond to the request with the content of the resourse
        required
        (parsing config file)

    ...store data from the request
        (accessing the proper file storage)

    ...use a configuration file, provided as an argument on the
        command line OR available in a defaul path

    ...remain non-blocking at all times and properly handle
        client disconnections when necessary

    ...use 1 poll()(or equivalent) for all the I/O operations
        between clients and the server(listen included)

    ...be compatible with standard web browsers

    ...define default error pages and response status codes

    ...work as a fully static website

    ...allow file upload

    ...Parse the GET, POST and DELETE methods

    ...be able to liste to multiple ports to deliver different
        contents(see Configuration file)

    ...support at least one CGI(php-CGI, Python, etc..)

    SHALL NOT...
    ...use errno after read or write to adjust the server
        behavior

    ...use poll()(or equivalent) to monitor both reading and
        writing simultaneously(read or write can only be used
        through a poll() or equivalent)

    ...make a request hang indefinitely

    ...not use fork for anything other than CGI(PHP, Python,
        etc..)


CONFIGURATION file

        SHALL...
        ...define all the interface: port pairs the server can
            to listen to

        ...set up default error pages

        ...set the maximum allowed size for client request bodies

        ...Specify rules or configurations on a URL/route(no
            regex required)  for a website, among the following:
            1. List of accepted HTTP methods for the route
            2. HTTP redirection
            3. Path of the requested file(URL /kapouet
                is rooted to /tmp/www, URL
                /kapouet/pouic/toto/pouet will search for
                /tmp/www/pouic/toto/pouet)
            4. Enabling or disabling directory listing
            5. Default file to serve when the request resource
                is a directory
            6. Uploading files from the clients to the server
                is authorized, and storage location is
                provided


CGI(Common Gateway Interface)

        SHALL...
        ...find the correct directory to run the requested
            process.

        ...run in the correct direcotry for relative path
            file access.

        ...work with the environment variables
            involved in the web-CGI communication.

        ...interpret the full request and arguments
            provided by the client.

        ...unchunk chunked requests, expecting EOF as the
            end of the body.

        ...send an EOF a the end of the output if no
            content_length is returned from the CGI.
            (THIS NEEDS A SERIOUS REVIEW)

EXTRAS:

    A. Please read the RFCs defining the HTTP protocol,
        and perform tests with telnet and NGINX before
        starting this project.
        Although you are not required to implement the
        entire RFCs, reading it will help you develop the
        required features.
        The HTTP 1.0 is suggested as a reference point,
        but not enforced.
    
    B. I/O that can wait for data (sockets, pipes/FIFOs,
        etc.) must be non-blocking and driven by a single
        poll() (or equivalent). Calling read/recv or
        write/send on these descriptors without prior
        readiness will result in a grade of 0.
        Regular disk files are exempt.
    
    C. We deliberately chose to offer only a subset of
        the HTTP RFC. In this context, the virtual host
        feature is considered out of scope. But
        you are allowed to implement it if you want.
    
    D.If you have a question about a specific behaviour,
        you can compare your program’s behaviour with
        NGINX’s. We have provided a small tester.
        Using it is not mandatory if everything works
        fine with your browser and tests, but it can
        help you find and fix bugs.
    
    F.Do not test with only one program. Write your tests
        in a more suitable language, such as Python or
        Golang, among others, even in C or C++ if you
        prefer.
    
    G. You can take inspiration from the ’server’ section
        of the NGINX configuration file.
